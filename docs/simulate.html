02 · One template

Is every flow one template? Yes.

Every scenario is the same three things: one event model, a set of lanes taken from the scenario, and one plug-in panel for what is special about it. The run view never changes; a new scenario is new data, not a new screen.

04 · Two agents, one owner beyond v0.4 · design exploration

Two agents for Alex, one gate, one ledger.

v0.4 runs one agent at a time (CONCEPT-IDEA §6). Scenario S5 explores what changes when a travel agent and a calendar agent work for the same person at once. They show up as two agent lanes and two task boards, in their own colours, writing to the same ledger.

Rule 1

No side channel

Agents never talk to each other directly. A hand-off is a request to the gate, which checks the receiver's purpose and forwards only that. The run view checks that there are no agent-to-agent arrows.

Rule 2

Own mandate, own scope

Each agent has its own mandate and tool scope. The calendar agent asks for the passport and is denied, without learning whether a passport exists.

Rule 3

One ledger, every entry tagged

Both agents write to the person's one chain. Each entry names the agent it was for, so the ledger can be filtered per agent without becoming two histories.

Rule 4

Minimal hand-offs

The travel agent publishes city and dates; the hotel and price stay behind. Colleagues see "busy", never where or why.

Rule 5

Stale plans are refused

Every action carries the plan version it was built on. When travel changes the itinerary, the calendar's older proposal is refused and re-planned: same action id, new attempt.

Rule 6

One queue for the person

Approvals from both agents land in one queue, grouped, so Alex decides once with the full picture, not twice in two apps.
